# auto_xxt_chrome_web — 学习通自动刷课脚本

基于 PyAutoGUI + 图像识别技术的前台自动化脚本，半自动操作 Chrome 浏览器中的学习通网页版。脚本能够模拟真人观看视频、自动静音播放、调整播放速度、检测并处理弹窗、自动跳转至下一节内容。

## 安装步骤

### 1. 克隆或下载项目

```bash
git clone git@github.com:123ewk/auto_xxt_chrome_web.git
cd auto_xxt_chrome_web
```

### 2. 创建并激活虚拟环境

**为什么要用虚拟环境？** 虚拟环境可以隔离项目的 Python 依赖，避免与系统其他 Python 项目产生包版本冲突。

```bash
# Windows CMD 用户：
python -m venv .venv
.venv\Scripts\activate

# Windows PowerShell 用户：
python -m venv .venv
.venv\Scripts\Activate.ps1

# Git Bash 用户：
python -m venv .venv
source .venv/Scripts/activate
```

激活成功后，命令行前面会出现 `(.venv)` 字样。

### 3. 安装依赖

```bash
pip install -r requirements.txt
```

这将自动安装以下库：
- **pyautogui** — 模拟鼠标点击和键盘操作
- **opencv-python** — 图像识别与模板匹配
- **numpy** — 图像数据处理
- **pynput** — 键盘/鼠标监听
- **loguru** — 日志记录

## 首次使用：截图模板

脚本需要先"认识"屏幕上的按钮长什么样，这个过程叫**模板截图**。只需做一次，除非学习通的界面改版了才需要重新截图。

### 运行截图引导工具

```bash
python main.py --calibrate
```

### 截图操作步骤

1. 运行上述命令后，脚本会依次提示每个模板名称
2. 确保对应的按钮/图标**在屏幕上是可见的**（打开学习通页面找到它）
3. 按回车后，你有 5 秒时间将鼠标移动到**要截取区域的左上角**
4. 再次按回车确认左上角位置
5. 然后将鼠标移动到**要截取区域的右下角**
6. 再次按回车确认右下角位置
7. 脚本会自动截取这个区域并保存为 PNG 图片

### 截图技巧

- **框选要精准**：只框选按钮本身，不要包含周围无关的背景
- **保持原始大小**：截取的图片会是运行时匹配的参照，不要缩放
- **不要移动窗口**：截图期间不要移动浏览器窗口或改变窗口大小
- **全部完成后再运行**：20 张模板都截完后再开始使用

### 查看模板状态

随时可以检查哪些模板已就绪、哪些还没截图：

```bash
python main.py --status
```

输出示例：

```
Templates: 15 ready, 5 missing
  Ready: play_button, next_section, complete_checkmark, ...
  Missing: quiz_option_c, quiz_option_d, quiz_confirm, ...
```

## 日常使用

### 基本用法

```bash
# 确保已激活虚拟环境
source .venv/Scripts/activate

# 运行脚本
python main.py
```

### 操作流程

1. **手动打开 Chrome 浏览器**
2. **登录学习通**（https://i.chaoxing.com）
3. **进入课程页面**，选择你要刷的课程
4. **找到有视频的章节**（可以从第一章开始）
5. **运行脚本** `python main.py`
6. **立即切换到 Chrome 窗口**（脚本有 5 秒倒计时）
7. **不要遮挡屏幕**，让脚本自动运行
8. 脚本会自动完成所有视频后提示完成

### 加速运行

```bash
# 1.5 倍速播放，给 10 秒准备时间
python main.py --speed 1.5 --countdown 10
```

## 命令行参数

| 参数 | 作用 | 默认值 | 详细说明 |
|------|------|--------|---------|
| `--calibrate` | 进入模板截图模式 | 无 | 引导式截取所有缺失的模板图片，首次使用必须运行 |
| `--status` | 查看模板状态 | 无 | 显示目前已截图和缺失的模板数量及名称 |
| `--speed N` | 设置播放速度倍率 | 2.0 | 支持 1.0（正常）、1.5、2.0 等数值。注意：加速被限制时会自动降级到 1x |
| `--countdown N` | 启动前的准备时间（秒） | 5 | 从运行命令到脚本开始操作之间的等待时间，用于切换到 Chrome 窗口 |

### 使用示例

```bash
# 最常用：1.5 倍速播放，准备时间延长到 8 秒
python main.py --speed 1.5 --countdown 8

# 保守模式：正常速度播放，准备时间 10 秒
python main.py --speed 1.0 --countdown 10

# 快速模式：2 倍速（默认），准备时间 3 秒
python main.py --countdown 3
```

## 运行原理

### 整体流程

```
用户手动打开 Chrome → 进入学习通课程页面 → 运行脚本
                            ↓
                     5 秒倒计时（切换到 Chrome 窗口）
                            ↓
                      ┌─────────────────────────────┐
                      │    步骤 1：检测弹窗           │
                      │    · 模板匹配已知弹窗按钮      │
                      │    · 轮廓检测发现未知弹窗区域  │
                      │    · 发现弹窗则自动点击确认    │
                      └─────────────────────────────┘
                            ↓
                      ┌─────────────────────────────┐
                      │    步骤 2：视频控制           │
                      │    · 检测播放按钮 → 点击播放  │
                      │    · DevTools 注入 JS 静音    │
                      │    · 再点播放器静音按钮双保险  │
                      │    · DevTools 注入 JS 加速    │
                      │    · 检测速度标签确认加速生效  │
                      └─────────────────────────────┘
                            ↓
                      ┌─────────────────────────────┐
                      │    步骤 3：监控进度           │
                      │    · 每 5 秒截图检测一次      │
                      │    · 检测"完成对勾"标记       │
                      │    · 检测"下一节"按钮是否出现  │
                      │    · 超时保护：最多等 10 分钟  │
                      └─────────────────────────────┘
                            ↓
                      ┌─────────────────────────────┐
                      │    步骤 4：导航到下一节       │
                      │    · 点击"下一节"按钮         │
                      │    · 或点击新解锁的章节       │
                      │    · 或返回课程列表重新进入    │
                      └─────────────────────────────┘
                            ↓
                  ↻ 回到步骤 1，重复循环 ↻
                            ↓
                   没有更多内容 → 脚本结束
```

### 核心模块说明

- **core/screenshot.py** — 屏幕截图、模板匹配（`pyautogui.locateOnScreen`）、OpenCV 轮廓检测
- **core/console.py** — 通过 Chrome DevTools（`Ctrl+Shift+I`）注入 JavaScript 代码，控制视频播放、静音、调速
- **core/clicker.py** — 封装 PyAutoGUI 的点击操作，支持重试机制和点击后验证
- **actions/video.py** — 视频处理主逻辑：播放 → 静音 → 加速 → 监控 → 完成检测
- **actions/navigation.py** — 检测并点击"下一节"、"返回课程"等导航按钮
- **actions/popup.py** — 弹窗识别，包括已知弹窗模板匹配和未知弹窗的轮廓检测

## 加速降级策略

学习通部分视频会限制倍速播放（不显示加速按钮），脚本针对这种情况设计了降级机制：

```
尝试 DevTools 注入 video.playbackRate = 2
            ↓
   等待 3 秒，检测 speed_2x 标签
            ↓
    ┌──── 检测到 2x 标签 ────→ 加速成功 ✅
    │
    └──── 未检测到 ────→ 重试一次
                ↓
        再次注入 playbackRate = 2
        再等待 3 秒检测
                ↓
         ┌── 检测到 2x 标签 ──→ 加速成功 ✅
         │
         └── 仍未检测到 ──→ 降级到 1x 正常速度 ⚠️
                     ↓
           日志记录警告："加速失败，已降级到 1x"
           视频继续以正常速度播放
```

这种设计确保即使加速失败，脚本也不会卡住，而是继续以正常速度完成播放。

## 安全机制

### 紧急停止：鼠标移到左上角

PyAutoGUI 内置了 fail-safe 机制：**运行过程中只要将鼠标移动到屏幕左上角（坐标 0,0），脚本会立即抛出异常停止运行。** 这是最重要的安全功能，出现任何异常情况时使用此方法紧急中止。

### 半自动设计：登录由你手动完成

脚本不处理登录过程。学习通的登录验证（验证码、扫码、短信等）由用户手动完成后再启动脚本。这避免了脚本处理复杂验证逻辑可能导致的账号风险。

### 超时保护

每个视频最多等待 10 分钟。如果视频时长超过 10 分钟或脚本未能检测到视频完成标记，超时机制会强制跳过当前视频，避免无限等待。

### 日志记录

所有操作都会记录到 `logs/session.log` 文件，包括：
- 每次点击的坐标
- JS 注入的执行情况
- 速度设置是否成功
- 弹窗检测结果
- 任何错误和警告信息

如果出现问题，可以查看日志文件排查。

## 常见问题

### Q：脚本运行后没有反应？

- 检查模板是否已经截图完整：`python main.py --status`
- 确认浏览器窗口在脚本启动时处于可见状态
- 检查是否有其他窗口遮挡了学习通页面

### Q：视频一直不播放？

- 确保视频页面上能看见播放按钮
- 检查 Chrome 开发者工具没有被禁用
- 某些特殊页面可能需要手动刷新后重新运行

### Q：加速不起作用？

- 这是预期的行为，脚本会自动降级到 1x 正常速度
- 查看日志确认降级原因
- 某些视频确实无法通过 JS 强制加速

### Q：弹窗没有被处理？

- 运行 `--calibrate` 重新截图弹窗相关模板
- 弹窗模板截图时尽量只框选按钮本身，不要包含背景
- 随堂测验目前默认选择 A 选项

## 注意事项

1. **运行期间不要遮挡屏幕** — 脚本依赖屏幕截图来识别按钮，被遮挡会导致匹配失败
2. **分辨率必须一致** — 模板截图时的屏幕分辨率必须与运行时的分辨率一致，否则模板匹配可能失败
3. **界面改版需重新截图** — 学习通网页偶尔会更新界面，如果按钮样式变了，需要重新运行 `--calibrate` 截图
4. **不要在敏感页面使用** — 建议只在纯视频章节页面使用，不要在考试、作业等页面使用
5. **建议用前检查状态** — 每次使用前运行 `python main.py --status` 确认模板齐全
6. **学习通检测机制** — 虽然脚本模拟了真人操作，但使用自动化工具仍可能存在账号风险，请自行评估
7. **日志保留** — 日志文件会持续增长，建议定期清理 `logs/session.log`
